## 给 Dot 的持久任务指令

每次执行时读取上述固定机器入口；不要读取缓存、按 Release 时间排序或自行寻找替代视频。

1. 读取固定入口，要求 `schemaVersion=2`、`kind=dot-publication-calendar`、`mode=publish`、`testOnly=false`，且选择策略为 `strict-today-only`。用当前时间换算北京时间日期，以该日期精确查找 `entries`。缺少今天的键就报告“今日无任务”并停止，绝不取最早、最新、未来或昨日任务。顶层索引不提供直接发布授权。
2. 取当天条目的 `taskFile`（相对仓库根目录，不是相对 daily/），下载该 JSON，校验原始 UTF-8 字节 SHA-256 等于 `taskSha256`；任务身份、日期、状态及授权必须与索引一致。条目与任务均须 `status=ready`、`submitAuthorized=true`，任务还须 `mode=publish`、`testOnly=false` 才能继续。blocked 时报告原因并停止。
3. 账号和具体几点执行交由 Dot 管理，未指定账号或具体时间不阻断。日期必须为今天；未到 notBefore 不提前提交，超过 expiresAt 不补发。每日任务默认北京时间 00:00 生效、次日 00:00 过期。每个账号每个北京时间自然日最多发布一条，不补发历史缺口。
4. 使用稳定的 `taskId` 和 `releaseId + renderSha256` 查持久执行记录，先原子领取任务，避免并发运行。如果无法持久记录、无法排除另一次执行或同日已发布，则停止。`account.id` 非空时必须匹配；为空时由 Dot 确定目标账号，并在本次上传、提交、查重和验证期间保持同一账号。不得因本地清单未指定账号而要求用户补填。登录失效或验证码需要用户处理。
5. 上传前检查官方作品列表和执行记录。发现同标题作品或不明确的提交，先保存证据并交由项目核对，禁止重复上传。单凭聊天声称“已发布”不能记为成功，也不能反向断定未发布。
6. 从 task.media.url 下载视频，核对大小及 SHA-256。只使用 task.copy 的标题、简介和话题；每个话题必须关联名称匹配的官方建议项。按 task.settings 核对所有选项，封面使用视频第 0 帧，须有可见场景、书名和作者。信息缺失、设置不符或话题不匹配时停止。
7. 最终提交前重新获取当前北京时间日期和固定入口，仍只读取当天 entries，确认当天 taskId、taskSha256 和授权状态未变（跨日须停止旧任务），并再次核对账号、时间窗口、标题、简介、话题、设置和视频。完成校验后可执行一次最终发布，不需要同范围的再次人工确认。
8. 提交后进入官方作品列表，确认准确标题及对应最近作品在“已发布”或“审核中”状态，记录作品 ID/链接与时间，保存匹配作品可见的当前视口截图（不截整页）。只有这些证据齐全才记为已验证完成。
9. 点击发布后超时、断网或结果不明，记为 `unverified`，停止发布动作并先检查官方列表。没有权威缺席证据和新的重试授权，不重新上传、不重复点击。执行异常、无任务或被阻断都要反馈实际结果。
10. 向用户交付 taskId、releaseId、视频哈希、账号、标题、时间、作品 ID/链接、平台状态与截图。证据和账号执行记录保存在用户私有位置，不上传公开仓库。本地项目只有验证证据后才同步发布队列；本入口不自动完成该同步。

## 本地维护

本地单日工具：`node scripts/export-dot-publication.mjs --position <n> --publish-date YYYY-MM-DD --media-url <HTTPS>`。它验证当前队列、生产账本、READY 发布包和媒体哈希，只导出允许公开的字段。

批量工具：`node scripts/export-dot-publication.mjs --plan <plan.json> --output .agents/dot-calendar-export`。计划格式为 `{"entries":[{"position":58,"publishDate":"2026-11-03","mediaUrl":"https://.../video.mp4"}]}`。日期必填；账号和具体时间可选，不要求用户补填。缺正式媒体地址会 blocked；`holdReason` 用于保留待核实阻断。同日不同任务、跨日重复作品、已发布或提交不明均阻断。不静默覆盖既有日期任务，历史日期保留。

正式媒体先上传并核对 GitHub 资产哈希，再上传 `daily/YYYY-MM-DD.json`，最后更新 `daily/current.json`，以同一 Git commit 原子更新文字材料。日期任务由索引中的 taskSha256 绑定，不能静默修改。旧 v1 导出拒绝自动覆盖，应使用新的输出目录并明确迁移远程索引。

当前仅启用三天排期，无需这三天内每天改 GitHub。其余已上传材料不在当前索引中，不构成可执行任务。到期后需继续补充后续日期，缺日期就停止。本次未建立定时器、跨设备任务锁或结果回写服务；Dot 仍需保存执行记录并按其自身日程读取入口，本地只在验证证据后同步生产状态。仅上传排期不意味着 Dot 的每日定时执行已配置。
