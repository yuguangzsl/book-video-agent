# Dot 双渠道日期发布任务

固定入口：https://raw.githubusercontent.com/yuguangzsl/book-video-agent/main/daily/current.json

用户已明确授权同一日期视频由 Dot 云电脑自动点击真实发布到抖音和小红书，无需本地 publish 脚本或小红书手动流程。账号和具体执行时间由 Dot 管理。此授权仅适用于 GitHub 的这三条任务，不修改本地规则、数据或发布队列。

## GitHub 发布数据的固定渠道规则

所有当前及今后上传到 GitHub 的正式发布任务，都必须同时包含 `douyin`（抖音）和 `xiaohongshu`（小红书），不得只提供单渠道任务。每个渠道必须有明确的专用标题、简介、话题、设置、授权状态和独立去重标识；两渠道可以使用相同视频及哈希。索引中的渠道信息必须与日期任务一致。

缺少任一渠道或任一渠道必要字段，整条任务均不得标为可执行；必须补齐后再更新固定入口。两个渠道均由 Dot 云电脑通过官方页面自动点击发布，按渠道独立记录结果和证据。仅一个渠道成功不能报告双渠道完成，补做另一个渠道时不得重复发布已成功的渠道。

本规则适用于 GitHub 发布数据，不自动修改本地文件或生产队列，也不构成对测试包、未就绪或日期不符任务的发布授权。除非用户明确修改本规则，否则后续新增日期任务也必须遵守双渠道要求。

## 职责边界

生产与 GitHub 数据准备阶段负责成片质量、库存、历史发布记录核实及排期去重；只有完成这些工作后才能导出 ready 且 submitAuthorized=true 的任务。Dot 把当天已授权任务视为可执行结论，仅下载材料、按渠道填写并发布、反馈实际结果。

Dot 不读取或恢复本地台账，不要求历史记录恢复，不原子领取任务，不以无法证明旧流程已排除或缺少跨设备锁为由阻断，不重复审核成片质量。已知的本次提交成功或结果不明仍须避免重复提交；这不要求发布前恢复全部历史。

## 执行要求

1. 每次读取 current.json，要求 schemaVersion=3、mode=publish、testOnly=false。用北京时间今天精确取 entries[YYYY-MM-DD]。没有当天任务就停止，禁止按 Releases 顺序挑选、提前或补发。夜的命名术未排入，需先核实是否已发布。
2. taskFile 相对仓库根目录。下载原始 JSON 字节，验证 SHA-256 等于 taskSha256，核对任务身份与日期。日期任务要求 schemaVersion=2、platform=multi-platform。旧单渠道执行器不支持本版本时必须停止，不能只发一个渠道。
3. 索引、日期任务和对应渠道都必须 status=ready、submitAuthorized=true，任务及渠道必须 mode=publish、testOnly=false。最终提交前重读当前入口并核对当天日期、任务哈希和授权未变。只在 schedule.notBefore 至 expiresAt 内执行，跨日停止。账号和具体时间交由 Dot 管理，不要求本地补填；同一渠道全过程保持同一账号。
4. 下载 task.media.url，核对字节数及 SHA-256。两渠道使用同一视频，按 platformOrder 先抖音后小红书。分别读取 platforms[渠道].copy、settings、execution、evidence。不能把一个渠道的文案当作另一个渠道的数据来源。标题限制：抖音30字，小红书20字。
5. 按当天任务执行，无需恢复历史发布记录、读取本地台账、原子领取或排除旧流程并发。任务与渠道标识用于关联本次结果；本次运行中成功的渠道不重复提交。每个渠道单独反馈结果，抖音成功不能代替小红书成功。
6. 直接通过 https://creator.douyin.com/ 和 https://creator.xiaohongshu.com/ 的官方页面上传，不把上传前检查历史作品列表或历史执行记录作为前置条件。不使用私有接口、不绕过验证码。若本次提交结果不明，再检查对应平台官方列表，避免重复上传。
7. 准确填写该渠道标题、简介；逐个选择名称匹配的官方建议话题，纯文本hashtag不算关联。封面取视频第0帧；书名、作者、画面亮度及成片质量由生产阶段完成校验，Dot 不重复审核。按该渠道 settings 设置页面提供的选项，可设置时按任务要求执行（包括关闭原创声明）。遇到页面没有提供或无法设置的选项（例如没有下载开关），保留平台默认设置并继续发布，无需再次请求确认。该回退规则优先于该不可设置选项的目标值和单独强制要求；不得编造设置映射或声称已核实目标值，结果中注明保留默认的选项。本规则适用于当前及今后的正式 GitHub 发布任务。
8. 全部核对通过后在对应渠道点击最终发布一次，无需同范围再次人工确认。登录失效、验证码需要用户处理。
9. 各渠道提交后都要检查官方作品/笔记管理列表，核对准确标题、最近作品、ID/链接及“已发布/审核中”，保存匹配作品可见的当前视口截图（fullPage=false）。证据齐全才记为该渠道已验证完成；截图和账号记录保存在用户私有位置，不上传公开仓库。
10. 某渠道结果不明时停止该渠道提交动作并核实，不马上重传或再次点击。另一渠道独立处理。只有两个渠道均有可信证据才报告双渠道完成；分别向用户交付每个渠道的状态、作品链接、时间、platformTaskId和截图。

## 数据版本

视频和哈希保持不变；渠道专用文案及设置来自同一不可变 release.json 的 publication.platforms 与 policy。Release 中原 export-manifest.json 是历史单渠道快照，已被当前日期任务替代；禁止根据旧快照忽略小红书。以 current.json 绑定的日期任务文件为唯一执行依据。

本入口不创建定时器，不修改本地发布队列。Dot 的持久任务提示词若仍包含旧的历史恢复、台账或并发排除前置条件，需要按本文职责边界更新。本地生成工具仍为单渠道版本，不应覆盖当前 v3 双渠道索引。

## 全部可发布库存信息

机器清单：[daily/inventory.json](inventory.json)。该清单按本地队列、生产台账、成片、QA 和 READY 发布包核验后导出，包含双渠道文案、设置、媒体参数和已核验的 GitHub 下载地址。账号、私有台账、凭证和本地路径不公开。

库存清单只供查看材料，不提供额外发布授权，也不改变现有日期排期。Dot 仍只执行 current.json 中今天的已授权任务；不得从库存中自行选片。media.url 为 null 表示视频尚未上传 GitHub。外部 Dot 结果未回写本地时，本地 pending 不代表平台实际尚未发布。

库存核验：本地待发布 20 部，可发布 20 部，待复核 0 部；已核验 GitHub 媒体 5 部，未上传 15 部。
